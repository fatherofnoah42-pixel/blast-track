# 爆破跑道 · 装置动画交付规范

这个文件夹里是一套能直接导入游戏的示例：`tower.can`（易拉罐投手）和 `shot.can`（易拉罐子弹）。
在游戏页面点「导入美术图片 / 动画」，把 4 个文件一起选上，就能看到效果。

## 每个造型交两个文件

| 文件 | 说明 |
| --- | --- |
| `tower.can.png` | 精灵图：所有帧排在一张透明 PNG 里 |
| `tower.can.json` | Aseprite「导出精灵图」时勾选 JSON Data 生成的文件（TexturePacker 的 JSON 也可以） |

## 动画段（Aseprite 里的 Tag）

| Tag | 用途 | 播放方式 |
| --- | --- | --- |
| `idle` | 待机 | 循环 |
| `fire` | 发射 | 播一次 |
| `release` | 只占 1 帧，标出子弹离手的那一帧（放在 fire 里面） | — |
| `build` | 放置时的动画（可选） | 播一次 |
| `fly` | 子弹飞行 | 循环 |
| `hit` | 子弹命中 | 播一次 |

## 定位点（Aseprite 里的 Slice）

| Slice | 用途 |
| --- | --- |
| `pivot` | 装置的脚底中心 / 子弹的中心。游戏把这个点放在石台中心或子弹位置上 |
| `muzzle` | 子弹出手的位置。可以每帧不同（Slice 加关键帧） |

## 画法约定

- 装置一律画**朝右的侧面**，敌人在左边时游戏会自动镜像。
- 子弹的 `fly` 也画**朝右**，游戏会沿弹道自动旋转。弹道本身不用画，由游戏计算（配置表「弹道」页可以调直线、抛物线、天降、速度和高度）。
- 按游戏内尺寸的 2–3 倍画，游戏会缩放到配置表「美术资源」里填的宽高。示例里装置每帧 120 × 150（游戏内 40 × 50），子弹每帧 36 × 36。
- 帧时长写在每帧的 duration 里（毫秒），idle 建议 120–200ms/帧，fire 50–90ms/帧。

## 文件命名

- 基础造型：`tower.<装置>.png`
- 路线变种：`tower.<装置>.A3.png`（A 路线成为主路线并升到 3 级起）、`tower.<装置>.A6.png`（6 级专精）。B、C 路线同理。没有 A4、A5 的图时沿用 A3。
- 子弹：`shot.<装置>.png`
- `<装置>` 可以写：`can` 易拉罐、`banana` 香蕉皮、`sprinkler` 洒水器、`drone` 无人机、`speaker` 音响、`chill` 休闲诱惑站、`miner` 矿机。

## 导不出 JSON 时

每段动画导出一串 PNG（例如 `can_A3_fire_01.png`、`can_A3_fire_02.png`…），打成 zip，再附一张表写明：每段几帧、每帧多少毫秒、第几帧出手、出手点和脚底点在图里的像素坐标。交给维护者拼成精灵图。
